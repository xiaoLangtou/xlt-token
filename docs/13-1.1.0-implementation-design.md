### Step 1.1 — Store 接口扩展 `keys()`

**为什么**：在线列表需要扫描 `session-list:*` 前缀的所有键，现有接口没有批量查询能力。

**改动：`src/store/xlt-token-store.interface.ts`**

```ts
export interface XltTokenStore {
  get(key: string): Promise<string | null>;
  set(key: string, value: string, timeoutSec: number): Promise<void>;
  delete(key: string): Promise<void>;
  has(key: string): Promise<boolean>;
  update(key: string, value: string): Promise<void>;
  updateTimeout(key: string, timeoutSec: number): Promise<void>;
  getTimeout(key: string): Promise<number>;

  // 新增：返回所有匹配 pattern 的 key 列表
  // pattern 语义：前缀匹配，以 '*' 结尾，如 'authorization:login:session-list:*'
  keys(pattern: string): Promise<string[]>;
}
```

**改动：`src/store/memory-store.ts`**

在 `MemoryStore` 类中添加：

```ts
async keys(pattern: string): Promise<string[]> {
  const prefix = pattern.endsWith('*')
    ? pattern.slice(0, -1)
    : pattern;
  const result: string[] = [];
  for (const [key] of this.store) {
    if (key.startsWith(prefix) && this.peek(key)) {
      result.push(key);
    }
  }
  return result;
}
```

**改动：`src/store/redis-store.ts`**

使用 Redis `SCAN` 迭代（避免 `KEYS` 阻塞）：

```ts
async keys(pattern: string): Promise<string[]> {
  const result: string[] = [];
  let cursor = 0;
  do {
    const reply = await this.client.scan(cursor, { MATCH: pattern, COUNT: 100 });
    cursor = reply.cursor;
    result.push(...reply.keys);
  } while (cursor !== 0);
  return result;
}
```

> **⚠️ 兼容性注意**：`redis@4` 的 `scan` 返回 `{ cursor, keys }`；`redis@3` 返回数组形式，需做版本判断（或在 test 中用 `redis@4` 锁定）。

### Step 1.2 — 多端登录 Session Key 重构

#### 1.2.1 存储键设计

| 键模板 | 值 | 说明 |
| --- | --- | --- |
| `${name}:login:session:${loginId}:${device}` | token | 每个设备独立 session，device 默认 `'default'`（1.0 兼容） |
| `${name}:login:session-list:${loginId}` | `JSON.stringify(DeviceInfo[])` | 全设备索引，用于列表查询和全量踢出 |
| `${name}:login:token:${token}` | loginId | 不变（校验链路不动） |
| `${name}:login:lastActive:${token}` | 毫秒时间戳 | 不变 |

```ts
interface DeviceInfo {
  device: string;
  token: string;
  loginTime: number;
}
```

#### 1.2.2 1.0 → 1.1 兼容策略

- **旧键格式**：`${name}:login:session:${loginId}`（无 device 段）
- **新键格式**：`${name}:login:session:${loginId}:default`
- 当 `device='default'`（默认值）时，`login()` 先读旧格式键，若存在则迁移（写新格式、删旧格式）
- 新部署直接写新格式，无历史数据可跳过迁移逻辑

**`login()` 改动**（核心逻辑）：

```ts
async login(
  loginId: string | number,
  options: { timeout?: number; device?: string; token?: string } = {},
): Promise<string> {
  // ... 校验 loginId ...

  const device = options.device ?? 'default';
  const timeout = options.timeout ?? this.config.timeout;

  // ── 读取该设备的旧 token ──
  const deviceSessionKey = this.sessionKey(_loginId, device);
  const oldDeviceToken = await this.store.get(deviceSessionKey);
    // 同时兼容 1.0 旧格式（仅 device='default' 时）
  const legacySessionKey = `${this.config.tokenName}:login:session:${_loginId}`;
  const legacyToken = device === 'default'
    ? await this.store.get(legacySessionKey)
    : null;

  const existingToken = oldDeviceToken ?? legacyToken;

  // ── 根据 deviceConcurrent + isConcurrent + isShare 决定行为 ──
  let token: string;

  if (!this.config.deviceConcurrent) {
    // 任意新登录踢掉所有设备（等价于 1.0 isConcurrent=false 的全局版）
    await this._kickoutAllDevices(_loginId);
    token = options.token ?? this.strategy.createToken(_loginId, this.config);
  } else if (!this.config.isConcurrent) {
    // 同设备互踢
    if (existingToken) await this._replacedToken(_loginId, existingToken);
    token = options.token ?? this.strategy.createToken(_loginId, this.config);
  } else if (this.config.isShare && existingToken) {
    // 同设备共享 token
    token = existingToken;
  } else {
    token = options.token ?? this.strategy.createToken(_loginId, this.config);
  }

  // ── 写入 ──
  await this.store.set(this.tokenKey(token), _loginId, timeout);
  await this.store.set(deviceSessionKey, token, timeout);

  // 迁移：清理 1.0 遗留的旧格式键
  if (legacyToken) await this.store.delete(legacySessionKey);

  // 更新全设备索引
  await this._addToSessionList(_loginId, { device, token, loginTime: Date.now() }, timeout);

  if (this.config.activeTimeout > 0) {
    await this.store.set(this.lastActiveKey(token), String(Date.now()), timeout);
  }

  // ── 触发钩子 ──
  this._callHook('onLogin', _loginId, token, device);

  return token;
}
```

**session-list 辅助方法**：

```ts
private async _addToSessionList(
  loginId: string,
  info: DeviceInfo,
  timeout: number,
): Promise<void> {
  const key = this.sessionListKey(loginId);
  const raw = await this.store.get(key);
  const list: DeviceInfo[] = raw ? JSON.parse(raw) : [];
  // 同 device 去重
  const idx = list.findIndex(d => d.device === info.device);
  if (idx >= 0) list.splice(idx, 1);
  list.push(info);
  await this.store.set(key, JSON.stringify(list), timeout);
}

private async _removeFromSessionList(loginId: string, device: string): Promise<void> {
  const key = this.sessionListKey(loginId);
  const raw = await this.store.get(key);
  if (!raw) return;
  const list: DeviceInfo[] = JSON.parse(raw);
  const filtered = list.filter(d => d.device !== device);
  if (filtered.length === 0) {
    await this.store.delete(key);
  } else {
    await this.store.set(key, JSON.stringify(filtered), -1); // 继承原 TTL 不变
  }
}
```

### Step 1.3 — 新增 API：`getDeviceList` / `kickoutByDevice` / `kickoutByToken`

在 `src/auth/stp-logic.ts` 中新增：

```ts
/**
 * 查询某账号所有在线设备
 */
async getDeviceList(loginId: string): Promise<DeviceInfo[]> {
  const raw = await this.store.get(this.sessionListKey(loginId));
  return raw ? JSON.parse(raw) : [];
}

/**
 * 踢掉指定设备
 */
async kickoutByDevice(loginId: string, device: string): Promise<boolean | null> {
  const token = await this.store.get(this.sessionKey(loginId, device));
  if (!token) return null;

  await this.store.update(this.tokenKey(token), NotLoginType.KICK_OUT);
  await this.store.delete(this.sessionKey(loginId, device));
  await this._removeFromSessionList(loginId, device);
  this._writeOfflineRecord(token, NotLoginType.KICK_OUT);
  this._callHook('onKickout', loginId, token);
  return true;
}

/**
 * 踢掉指定 token
 */
async kickoutByToken(token: string): Promise<boolean | null> {
  const loginId = await this.store.get(this.tokenKey(token));
  if (!loginId || [NotLoginType.KICK_OUT, NotLoginType.BE_REPLACED].includes(loginId as any)) {
    return null;
  }

  await this.store.update(this.tokenKey(token), NotLoginType.KICK_OUT);
  // 从 session-list 中找到对应 device 并删除
  const list = await this.getDeviceList(loginId);
  const info = list.find(d => d.token === token);
  if (info) {
    await this.store.delete(this.sessionKey(loginId, info.device));
    await this._removeFromSessionList(loginId, info.device);
  }
  this._writeOfflineRecord(token, NotLoginType.KICK_OUT);
  this._callHook('onKickout', loginId, token);
  return true;
}
```

**`logout()` 需要同步清理 session-list**：

在现有 `logout()` 末尾补充：

### Step 1.4 — 观测性 API：`getOnlineLoginIds` / `getOnlineCount` / `forceLogout`

依赖 Step 1.1 的 `store.keys(pattern)`。

```ts
/**
 * 查询所有在线 loginId（分页）
 */
async getOnlineLoginIds(opts: { page?: number; pageSize?: number } = {}): Promise<string[]> {
  const { page = 0, pageSize = 100 } = opts;
  const pattern = `${this.config.tokenName}:login:session-list:*`;
  const keys = await this.store.keys(pattern);
  const prefix = `${this.config.tokenName}:login:session-list:`;
  const start = page * pageSize;
  return keys
    .slice(start, start + pageSize)
    .map(k => k.slice(prefix.length));
}

/**
 * 在线用户数
 */
async getOnlineCount(): Promise<number> {
  const pattern = `${this.config.tokenName}:login:session-list:*`;
  const keys = await this.store.keys(pattern);
  return keys.length;
}

/**
 * 强制某账号所有设备下线
 */
async forceLogout(loginId: string): Promise<void> {
  const list = await this.getDeviceList(loginId);
  for (const { device } of list) {
    await this.kickoutByDevice(loginId, device);
  }
}
```

#### 1.5.3 统一调用点

在 `StpLogic` 中添加安全调用方法（钩子异常绝不能影响主流程）：

```ts
private _callHook<K extends keyof XltHooks>(
  name: K,
  ...args: Parameters<NonNullable<XltHooks[K]>>
): void {
  if (!this.hooks?.[name]) return;
  try {
    const result = (this.hooks[name] as any)(...args);
    if (result instanceof Promise) {
      result.catch(err => console.error(`[xlt-token] hook ${name} error:`, err));
    }
  } catch (err) {
    console.error(`[xlt-token] hook ${name} error:`, err);
  }
}
```

调用位置：

| 方法 | 钩子 | 时机 |
| --- | --- | --- |
| `login()` 末尾 | `onLogin(loginId, token, device)` | 写入成功后 |
| `logout()` 末尾 | `onLogout(loginId, token, 'logout')` | 删除 key 后 |
| `_replacedToken()` | `onReplaced(loginId, oldToken, newToken)` | 写 BE_REPLACED 后 |
| `kickout()` / `kickoutByDevice()` / `kickoutByToken()` | `onKickout(loginId, token)` | 写 KICK_OUT 后 |

## Milestone 2 · 二级认证 + 临时 Token

### Step 2.1 — 存储键与核心 API

#### 存储键

```
${name}:safe:${token}:${business}       → String(Date.now())（标记打开时间）
${name}:temp-token:${tempToken}         → 业务值（任意字符串）
```

#### `StpLogic` 新增方法

```ts
// ── 二级认证 ──

/**
 * 打开二级认证窗口
 * @param token     用户 token（从 request 中取）
 * @param business  业务标识，如 'pay' / 'deleteAccount'
 * @param timeout   有效期（秒）
 */
async openSafe(token: string, business: string, timeout: number): Promise<void> {
  await this.store.set(this.safeKey(token, business), String(Date.now()), timeout);
}

/**
 * 校验二级认证是否有效
 * 未通过时抛 NotSafeException
 */
async checkSafe(token: string, business: string): Promise<void> {
  const exists = await this.store.has(this.safeKey(token, business));
  if (!exists) throw new NotSafeException(business);
}

/**
 * 主动关闭二级认证（如用完即关）
 */
async closeSafe(token: string, business: string): Promise<void> {
  await this.store.delete(this.safeKey(token, business));
}

// ── 临时 Token ──

/**
 * 创建一次性/短效临时 token
 * @param value    要关联的业务数据（字符串，如 'resetPwd:userId=1001'）
 * @param timeout  有效期（秒）
 * @returns        临时 token 字符串
 */
async createTempToken(value: string, timeout: number): Promise<string> {
  const tempToken = this.strategy.createToken('__temp__', this.config);
  await this.store.set(this.tempTokenKey(tempToken), value, timeout);
  return tempToken;
}

/**
 * 解析临时 token（读取，不自动删除）
 * 需要一次性语义时，解析后调 deleteTempToken
 */
async parseTempToken(tempToken: string): Promise<string | null> {
  return this.store.get(this.tempTokenKey(tempToken));
}

/**
 * 销毁临时 token
 */
async deleteTempToken(tempToken: string): Promise<void> {
  await this.store.delete(this.tempTokenKey(tempToken));
}

// ── Key helpers ──
private safeKey(token: string, business: string): string {
  return `${this.config.tokenName}:safe:${token}:${business}`;
}

private tempTokenKey(tempToken: string): string {
  return `${this.config.tokenName}:temp-token:${tempToken}`;
}
```

## Milestone 3 · JWT Strategy

### Step 3.1 — 新建 `src/token/jwt-strategy.ts`

**依赖**：`jsonwebtoken` 作为 peer dependency（不强依赖，只在使用时安装）。

```ts
import { Inject, Injectable, Optional } from '@nestjs/common';
import { sign, verify, JwtPayload } from 'jsonwebtoken';
import { XLT_TOKEN_CONFIG, XltTokenConfig } from '../core/xlt-token-config';
import type { TokenStrategy } from './token-strategy.interface';

@Injectable()
export class JwtStrategy implements TokenStrategy {
  constructor(
    @Inject(XLT_TOKEN_CONFIG) private readonly config: XltTokenConfig,
  ) {}

  createToken(loginId: string, config: XltTokenConfig): string {
    const jwt = config.jwt!;
    const jti = crypto.randomUUID();  // 唯一标识，用于黑名单

    return sign(
      { sub: loginId, jti },
      jwt.secret,
      {
        algorithm: jwt.algorithm ?? 'HS256',
        ...(jwt.issuer && { issuer: jwt.issuer }),
        ...(jwt.audience && { audience: jwt.audience }),
        ...(config.timeout > 0 && { expiresIn: config.timeout }),
      },
    );
  }

  generateToken(payload: any): string {
    return sign(payload, this.config.jwt!.secret);
  }

  verifyToken(token: string): JwtPayload & { sub: string; jti: string } {
    return verify(token, this.config.jwt!.secret) as any;
  }
}
```

### Step 3.2 — `_resolveLoginId` 的 JWT 分支

JWT 模式下登录态验证分为两步：
1. 本地 JWT verify（0 IO）→ 得到 `loginId` 和 `jti`
2. 检查黑名单 `jwt-blacklist:<jti>`（1 IO）→ 确认未被踢/顶

> **与 UUID 模式对比**：UUID 模式每次鉴权需要 1 次 store 查询（tokenKey → loginId）；JWT 模式降为黑名单查询（只有被踢/顶的 token 才有记录）。

**`_resolveLoginId` 改动**：

```ts
private async _resolveLoginId(req: Request) {
  const token = await this.getTokenValue(req);
  if (!token) return { ok: false, reason: NotLoginType.NOT_TOKEN };

  // ── JWT 分支 ──
  if (this._isJwtMode()) {
    return this._resolveLoginIdJwt(token);
  }

  // ── UUID 分支（现有逻辑不变）──
  const loginId = await this.store.get(this.tokenKey(token));
  // ...
}

private _isJwtMode(): boolean {
  // 通过判断 strategy 是否有 verifyToken 且 jwt config 存在
  return !!(this.config.jwt?.secret && typeof (this.strategy as any).verifyToken === 'function');
}

private async _resolveLoginIdJwt(
  token: string,
): Promise<{ ok: boolean; loginId?: string; token?: string; reason?: NotLoginType }> {
  try {
    const payload = this.strategy.verifyToken(token);
    const { sub: loginId, jti } = payload;
    if (!loginId || !jti) return { ok: false, reason: NotLoginType.INVALID_TOKEN, token };

    // 黑名单检查（1 IO）
    const blacklisted = await this.store.get(this.jwtBlacklistKey(jti));
    if (blacklisted === NotLoginType.KICK_OUT)    return { ok: false, reason: NotLoginType.KICK_OUT, token };
    if (blacklisted === NotLoginType.BE_REPLACED) return { ok: false, reason: NotLoginType.BE_REPLACED, token };

    // activeTimeout 检查
    if (this.config.activeTimeout > 0) {
      const lastStr = await this.store.get(this.lastActiveKey(jti)); // 注意：用 jti 而非 token
      if (!lastStr) return { ok: false, reason: NotLoginType.TOKEN_FREEZE, token };
      const idle = (Date.now() - Number(lastStr)) / 1000;
      if (idle > this.config.activeTimeout) return { ok: false, reason: NotLoginType.TOKEN_TIMEOUT, token };
      await this.store.update(this.lastActiveKey(jti), String(Date.now()));
    }

    return { ok: true, loginId, token };
  } catch {
    // JWT 签名验证失败或已过期
    return { ok: false, reason: NotLoginType.INVALID_TOKEN, token };
  }
}

private jwtBlacklistKey(jti: string): string {
  return `${this.config.tokenName}:jwt-blacklist:${jti}`;
}
```

#### JWT 模式下的 `login()` 调整

JWT 模式下，`tokenKey` 不再写入（loginId 由 JWT 携带），但 `sessionKey` 仍然写入（保存 jti，用于 kickout）：

```ts
if (this._isJwtMode()) {
  // 解码新 token 取 jti
  const { jti } = this.strategy.verifyToken(token);
  // sessionKey 存 jti（不存完整 token，节省空间）
  await this.store.set(this.sessionKey(_loginId, device), jti, timeout);
  // activeTimeout 用 jti 作为 key
  if (this.config.activeTimeout > 0) {
    await this.store.set(this.lastActiveKey(jti), String(Date.now()), timeout);
  }
} else {
  // UUID 模式：现有逻辑
  await this.store.set(this.tokenKey(token), _loginId, timeout);
  await this.store.set(this.sessionKey(_loginId, device), token, timeout);
}
```

#### JWT 模式下的 `kickout()` / `replaced()` 调整

```ts
// kickout：写黑名单而非改 tokenKey
if (this._isJwtMode()) {
  const jti = await this.store.get(this.sessionKey(loginId, device));
  if (jti) await this.store.set(this.jwtBlacklistKey(jti), NotLoginType.KICK_OUT, ttl);
} else {
  await this.store.update(this.tokenKey(token), NotLoginType.KICK_OUT);
}
```

## 关键决策记录

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| session-list 存储格式 | JSON 数组存入 Store | 避免 Redis 依赖（MemoryStore 也能支持），代价是小量写放大 |
| `keys()` 方法语义 | 前缀匹配，`*` 结尾 | 只需简单 prefix scan，无需完整 glob 语义 |
| JWT 黑名单键 | 以 `jti` 为键而非 token | jti 更短，且 token 可能很长（JWT 本体） |
| JWT `activeTimeout` key | 用 `jti` 替代 `token` | token 存入 lastActive key 会让键过长 |
| 钩子异常处理 | try-catch 吞掉，console.error | 钩子是观测性的，不应让观测失败影响业务 |
| temp-token 生成器 | 复用 `strategy.createToken` | 不引入额外依赖；临时 token 不携带业务语义，UUID/random-32 足够 |
| `@XltCheckSafe` 消费位置 | Guard（`canActivate`） | 与现有 `@XltCheckPermission` 一致，减少学习成本 |
| JWT peer dependency | `jsonwebtoken` 而非 `@nestjs/jwt` | 不绑死 NestJS，2.0 多框架兼容性更好 |
